# 中华绒螯蟹基因组数据库系统 - 部署更新文档

## 更新流程概述

本文档详细说明了系统各组件的更新部署流程，确保在不影响服务可用性的前提下完成系统更新。

## 更新类型

### 1. 前端更新
适用于：UI界面修改、前端逻辑调整、样式更新等

### 2. 后端更新  
适用于：API接口修改、业务逻辑调整、数据库操作变更等

### 3. 文件服务更新
适用于：文件下载逻辑修改、文件管理功能调整等

### 4. 配置更新
适用于：nginx配置、数据库配置、环境变量等

## 前端更新流程

### 步骤1：代码更新
```bash
cd /mnt/d/workspace/proj-c/demo

# 拉取最新代码
git pull origin main

# 安装新依赖（如有）
cd crab-frontend-v3 && npm install && cd ..
```

### 步骤2：构建新版本
```bash
# 构建生产版本
cd crab-frontend-v3
npm run build

# 验证构建成功
ls -la dist/
cd ..
```

### 步骤3：验证更新
```bash
# 前端更新后无需重启nginx，直接访问验证
curl -I http://localhost/

# 外网验证（需natapp运行）
curl -I http://mittencrab.nat100.top/
```

**注意**: 前端更新无需重启任何服务，构建完成后即时生效。

## 后端更新流程

### 步骤1：代码更新和构建

## 数据库更新流程

### 1. 数据库结构更新
```sql
-- 在Windows MySQL环境执行
mysql -u root -p crab_database

-- 执行结构变更脚本
SOURCE /path/to/update.sql;

-- 验证表结构
SHOW TABLES;
DESCRIBE table_name;
```

### 2. 数据迁移
```powershell
# 在Windows环境备份重要数据
mysqldump -u root -p crab_database > backup_%date:~0,4%%date:~5,2%%date:~8,2%_%time:~0,2%%time:~3,2%%time:~6,2%.sql

# 执行数据迁移脚本
mysql -u root -p crab_database < /path/to/migration.sql
```

### 3. 重启相关服务
```bash
# 数据库结构变更后需要重启后端服务
./deploy/stop.sh
./deploy/start.sh
```

## 配置更新流程

### Nginx配置更新
```bash
# 备份当前配置
sudo cp /etc/nginx/sites-available/default /etc/nginx/sites-available/default.backup

# 编辑配置文件
sudo nano /etc/nginx/sites-available/default

# 测试配置
sudo nginx -t

# 重新加载配置（无需重启）
sudo systemctl reload nginx
```


## 完整系统更新流程

### 1. 准备阶段
```bash
# 创建更新日志
echo "$(date): 开始系统更新" >> deploy/logs/update.log

# 备份关键配置
cp src/main/resources/application.yaml config_backup/
cp /etc/nginx/sites-available/default config_backup/

# 数据库备份（在Windows环境执行）
mysqldump -u root -p crab_database > backup/crab_database_%date:~0,4%%date:~5,2%%date:~8,2%_%time:~0,2%%time:~3,2%%time:~6,2%.sql
```

### 2. 更新代码
```bash
cd /mnt/d/workspace/proj-c/demo

# 拉取最新代码
git pull origin main

# 更新前端依赖
cd crab-frontend-v3
npm install

# 更新文件服务依赖
cd ../server

```

### 3. 构建新版本
```bash
# 构建后端
mvn clean package -DskipTests

```

# 等待服务启动

### 5. 验证更新
```bash

```

## 回滚流程

### 快速回滚
```bash
# 使用git回滚到上一个版本
git reset --hard HEAD~1

# 重新构建和部署
mvn clean package -DskipTests
cd crab-frontend-v3
npm run build
cd ..

# 重启服务
./deploy/stop.sh
./deploy/start.sh
```

### 数据库回滚
```powershell
# 在Windows环境恢复数据库备份
mysql -u root -p crab_database < backup/crab_database_YYYYMMDD_HHMMSS.sql
```

### 配置回滚
```bash
# 恢复配置文件
cp config_backup/application.yaml src/main/resources/
sudo cp config_backup/default /etc/nginx/sites-available/

# 重新加载配置
sudo nginx -t && sudo systemctl reload nginx
```

## 常见更新问题

### 1. 前端构建失败
```bash
# 清理node_modules重新安装
rm -rf node_modules package-lock.json
npm install

# 检查Node.js版本兼容性
node --version
npm --version
```

### 2. 后端启动失败
```bash
# 检查Java版本
java -version

# 检查端口占用
netstat -tlnp | grep 3002

# 查看详细错误日志
tail -f deploy/logs/backend.log
```

### 3. 数据库连接失败
```bash
# 测试数据库连接
mysql -h 172.20.112.1 -u root -p crab_database

# 检查防火墙设置
# 确认WSL可以访问Windows IP
```

### 4. 外网访问异常
- 检查natapp客户端状态
- 验证域名解析是否正确
- 确认WSL服务正常运行

## 最佳实践

1. **定期更新**: 建议每周检查代码更新，每月进行一次完整系统更新
2. **测试优先**: 所有更新先在测试环境验证，再部署到生产环境
3. **备份策略**: 每次更新前必须备份数据库和关键配置
4. **监控告警**: 设置关键服务监控，及时发现问题
5. **文档记录**: 记录每次更新的内容、时间和影响
